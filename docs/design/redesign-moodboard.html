Spec อิง Supabase Dashboard แบบ dark ล้วน และใช้เขียว #3ECF8E เป็นสีหลัก เหมาะกับ dev ที่แก้ schema แต่ staff ที่กรอกข้อมูลทั้งวันจะล้าตาและรู้สึกว่าเป็นเครื่องมือเทคนิค

ฟอนต์ไม่รองรับภาษาไทย

--font-sans: 'Public Sans' ไม่มี glyph ไทย ชื่อ field, label และข้อมูลที่เป็นภาษาไทยจึงตกไปใช้ฟอนต์สำรองของระบบ ทำให้น้ำหนักตัวอักษรและ baseline ไม่ตรงกัน

Builder กับงานประจำวันอยู่ปนกัน

Sidebar เดียวรวมทั้ง Apps, Reports และเมนู Admin 8 รายการ staff เห็นเมนูที่ไม่เกี่ยวกับงาน ส่วน admin สลับไปมาระหว่าง “ใช้” กับ “สร้าง” ได้ยาก

หน้า builder แน่นเกินไป

admin/meta/entity.vue ยาว 2,316 บรรทัด และ app/[entity].vue ยาว 1,843 บรรทัด แปลว่ามีหลายหน้าที่รวมอยู่ในหน้าเดียว ควรแตกเป็น pane และ inspector

Workflow ไม่ได้อยู่ในหน้า record

สถานะแสดงเป็นแค่ badge ผู้ใช้จึงไม่เห็นว่า record อยู่ขั้นไหนของ flow และขั้นต่อไปคืออะไร ทั้งที่ workflow แบบ linear คือจุดแข็งของระบบ

Dashboard เป็นแค่ตัวเลขนับ

dashboard.vue แสดงเพียงยอดนับตาม status ของ entity เดียว ยังไม่มีหน้า “งานของฉัน” ที่บอก staff ว่าวันนี้ต้องทำอะไร

ข้อเสนอ: Workspace + Studio

ใช้ข้อมูลชุดเดียวกันแต่แยกเป็น 2 โหมด สลับได้ที่มุมล่างของ sidebar โดย staff จะเห็นแค่ Workspace โครงหน้าใช้แบบ B คือเรียบ ไว และมี ⌘K ส่วนหน้า record ยืมรูปแบบจาก C และ admin ยังได้เครื่องมือแม่นยำแบบ D

Workspace สำหรับงานประจำวัน

เปิดมาเจอหน้า “งานของฉัน” ก่อน แล้วค่อยเข้าไปที่ app และ entity

  • List มี view tabs ได้แก่ Table, Board (จัดกลุ่มตาม status), Calendar (ถ้ามี date field) และ saved views
  • หน้า record เปิดเป็น side panel ใช้เส้น workflow track แสดงว่าอยู่ขั้นไหน และปุ่ม transition แสดงเฉพาะที่ role นี้กดได้
  • Timeline การเปลี่ยนแปลงกับ related counts อยู่คอลัมน์ขวา
  • Light mode เป็นค่าเริ่มต้น ส่วนความหนาแน่นเลือกได้ระหว่าง comfortable กับ compact

Studio สำหรับสร้าง module

Builder ทุกตัวใช้โครง 3 pane เดียวกัน คือ โครงสร้าง ← canvas → inspector

  • ซ้ายเป็นต้นไม้ของ module (entities, forms, views, workflow, roles, reports)
  • กลางเป็นรายการ field แบบ block ลากเรียงได้ กด “/” เพื่อเพิ่ม field เหมือน Tally
  • ขวาเป็น inspector ของ field ที่เลือก ไม่ใช้ modal
  • แถบ draft/publish ติดอยู่ด้านล่างเสมอ แสดงว่ามีการเปลี่ยนแปลงกี่รายการที่ยังไม่ publish

Pattern ที่ควรศึกษาเพิ่ม

Form builder

ใช้แบบเอกสาร กด “/” เพื่อแทรก block ร่วมกับ inspector ด้านขวา

Tally, Fillout, builder 3 pane ของ Retool

Workflow editor

เป็นรายการ state ที่ลากเรียงได้ มีสี มี default state และแสดงผลในหน้า record เป็น track

Linear workflows, statusbar ของ Odoo

Permission matrix

แถวคือ entity (จัดกลุ่มตาม module) คอลัมน์คือ action และเซลล์มี 3 สถานะ: อนุญาต, ไม่อนุญาต และบางส่วน

saasui.design, shadcn permission matrix

Board / Calendar

ลากการ์ดข้ามคอลัมน์เพื่อเปลี่ยน status โดยต้องผ่านกฎ transition

Command palette

จัดกลุ่ม records กับ actions ไว้ด้วยกัน และวาง palette ชิดด้านบนจอแทนกึ่งกลาง

Retool blog, uxpatterns.dev

Empty states

แยกเป็น 3 แบบ คือใช้ครั้งแรก, ไม่พบผลลัพธ์ และ error แต่ละแบบมี action หลักหนึ่งอย่าง

nuxt-ui-templates/dashboard OSS, Nuxt UI v4

ลำดับการทำ

  1. เปลี่ยน token และฟอนต์ ใน main.css กับ app.config.ts ใช้ Plex Sans Thai และสี Horizon ให้ light mode เป็นค่าเริ่มต้น ทุกหน้าจะเปลี่ยนตามทันทีโดยไม่ต้องแก้ทีละหน้า
  2. แยก shell เป็น Workspace และ Studio ใน layouts/default.vue และซ่อน Studio จาก role ที่ไม่ใช่ admin
  3. ทำ component WorkflowTrack และ RecordTimeline แล้วนำไปใส่ใน side panel ของ app/[entity].vue
  4. ปรับ Entity Manager เป็น 3 pane โดยแตก entity.vue ออกเป็น FieldList, FieldInspector และ ModuleTree
  5. เพิ่มหน้า “งานของฉัน” แทน dashboard แบบนับ status โดยใช้ saved view ที่ filter ตามผู้ใช้
